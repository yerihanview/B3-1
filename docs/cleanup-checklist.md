- EBS 볼륨: `vol-0c4580477a8d7380c` (8 GiB, EC2 종료 시 삭제 설정)

**사전 확인이 필요한 항목:** Elastic IP(EIP), NAT Gateway, Load Balancer(ELB/ALB), RDS 및 기타 추가 리소스의 생성 여부. EC2에 현재 연결된 공개 IPv4 주소가 있다고 해서 EIP가 할당되었다는 뜻은 아니다.

## 3. 권장 정리 순서

> 리소스 삭제 시 의존성이 있다. 아래 항목은 **실행 기록**이며, 개별 삭제와 VPC 콘솔 통합 삭제를 구분한다.

### ① 컴퓨트 및 스토리지

- [x] EC2 인스턴스 `i-0fabb53623ab701ca`를 **Terminate**했다.
- [x] EC2가 `terminated` 상태임을 콘솔에서 확인했다.
- [x] 연결 EBS 볼륨 `vol-0c4580477a8d7380c`가 검색되지 않고 전체 볼륨 목록도 비어 있음을 확인했다.
- [x] 서울 리전의 EBS Volumes 전체 목록이 비어 있음을 확인했다.
- [x] 서울 리전의 'Owned by me' Snapshot 및 AMI 목록이 비어 있음을 확인했다.

### ② 추가 과금 리소스 점검

- [x] 서울 리전 Elastic IP 목록이 비어 있음을 확인했다(해당 없음).
- [x] 서울 리전 NAT Gateway 목록이 비어 있음을 확인했다(해당 없음).
- [x] Load Balancer는 사용자가 미생성이라고 확인했다. **콘솔 직접 조회는 IAM `AccessDenied`로 불가**했다.
- [x] RDS는 사용자가 미생성이라고 확인했다(콘솔 조회 근거 없음).

### ③ 네트워크

- [x] 실습용 Security Group의 VPC가 삭제되었고, 콘솔에서 남은 `default` 그룹은 ID와 VPC ID가 모두 다른 것을 확인했다.
- [x] VPC 통합 삭제 후 Subnet `subnet-0543e9e86dee40c3d`의 CLI 조회가 `InvalidSubnetID.NotFound`임을 확인했다.
- [x] Internet Gateway `igw-067455c9fc1f5aee8` 삭제를 콘솔에서 확인했다(VPC 통합 삭제 방식).
- [x] 메인 Route Table `rtb-0d27123bfa1fd03fe`는 VPC 통합 삭제에 따라 정리된 것으로 판단한다(개별 ID 직접 조회는 미실시).
- [x] 실습용 Security Group은 VPC 통합 삭제에 따라 정리된 것으로 판단한다(개별 ID 직접 조회는 미실시).
- [x] VPC `vpc-0442e2bd8ce7ff488` 통합 삭제 성공 및 콘솔 재조회에서 검색 결과 없음을 확인했다.
- [x] VPC·Subnet·IGW 삭제를 확인했고 다른 VPC의 기본 SG만 확인했다. SG/Route Table 개별 ID 직접 조회는 미실시.

**참고:** 콘솔에서 VPC 전체 삭제 기능을 사용하면 일부 하위 리소스를 함께 정리할 수 있다. 어느 방법을 택하든 삭제 결과를 재조회해야 한다. 다른 서비스가 리소스를 사용 중이면 의존성을 먼저 해소해야 한다.
