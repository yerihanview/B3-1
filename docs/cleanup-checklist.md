# B3-1 리소스 정리 체크리스트

> **상태: 정리 전 / 미완료**  
> 이 문서는 AWS 리소스의 **삭제 작업을 실행한 기록이 아니라**, 실습 종료 시 실행할 절차와 완료 근거를 기록하기 위한 체크리스트다.  
> **주의:** 삭제는 되돌릴 수 없다. `docs/architecture.md`, `docs/mission-verification.md`, `docs/troubleshooting.md`와 증빙 파일이 GitHub에 안전하게 저장된 것을 확인하고, 서비스 공개가 더 이상 필요 없을 때 실행한다.

## 1. 정리 대상과 범위

- 리전: `ap-northeast-2` (서울)
- 작업 프로필: `b3-1`
- EC2 인스턴스: `i-0fabb53623ab701ca`
- EBS 볼륨: `vol-0c4580477a8d7380c` (8 GiB, EC2 종료 시 삭제 설정)
- VPC: `vpc-0442e2bd8ce7ff488`
- Public Subnet: `subnet-0543e9e86dee40c3d`
- Internet Gateway: `igw-067455c9fc1f5aee8`
- 메인 Route Table: `rtb-0d27123bfa1fd03fe`
- Security Group: `sg-0acdbff1f820fee1b`
- 사용 도메인: `codyssey-b3-1-test.duckdns.org` (DuckDNS, AWS 리소스가 아님)

**사전 확인이 필요한 항목:** Elastic IP(EIP), NAT Gateway, Load Balancer(ELB/ALB), RDS 및 기타 추가 리소스의 생성 여부. EC2에 현재 연결된 공개 IPv4 주소가 있다고 해서 EIP가 할당되었다는 뜻은 아니다.

## 2. 정리 전 보존 및 안전 확인

- [ ] GitHub Private 저장소에 최종 README, 다이어그램, 보고서, 검증서, 증빙을 Push했다.
- [ ] 증빙의 비밀정보(토큰·비밀번호·개인 키 등) 마스킹을 재확인했다.
- [ ] 필요한 Nginx 설정과 컨테이너 실행 정보, 접속·검증 결과를 보존했다.
- [ ] EC2 종료 시 서비스와 공개 IP 접속이 끊기며, 재구축이 필요해질 수 있음을 확인했다.
- [ ] 필요하다면 DuckDNS DNS 레코드/갱신 설정과 HTTPS 인증서 운영 종료 계획을 확인했다.
- [ ] 삭제 대상을 AWS 콘솔 또는 CLI로 재조회하여 *현재 리소스 ID*와 일치하는지 확인했다.

## 3. 권장 정리 순서

> 리소스 삭제 시 의존성이 있다. 각 항목을 실행한 뒤 **삭제 완료 상태를 다시 조회하고 결과를 기록**한다. 아래 절차는 계획이며, 아직 실행했다고 표시하지 않는다.

### ① 컴퓨트 및 스토리지

- [ ] EC2 인스턴스 `i-0fabb53623ab701ca`를 **Terminate**했다. (`Stop`만으로는 최종 정리가 아님)
- [ ] EC2가 `terminated` 상태인지 확인했다.
- [ ] 연결 EBS 볼륨 `vol-0c4580477a8d7380c`의 실제 삭제 여부를 확인했다. `DeleteOnTermination=true`는 예정된 동작이므로 결과를 재확인한다.
- [ ] 별도로 남아 있는 미사용 EBS 볼륨이 없는지 확인하고 필요한 경우 삭제했다.
- [ ] 추가 과금 가능 항목인 EBS Snapshot/AMI 등 생성 여부를 확인하고, 실습용으로 남은 자원을 정리했다.

### ② 추가 과금 리소스 점검

- [ ] Elastic IP 할당 여부를 확인했다. 할당했다면 연결 해제 후 **Release**했다. 미생성이라면 `해당 없음`으로 기록한다.
- [ ] NAT Gateway 생성 여부를 확인했다. 생성했다면 삭제 완료를 확인한다. 없으면 `해당 없음`.
- [ ] ELB/ALB 생성 여부를 확인했다. 생성했다면 삭제 완료를 확인한다. 없으면 `해당 없음`.
- [ ] RDS 생성 여부를 확인했다. 생성했다면 삭제 완료를 확인한다. 없으면 `해당 없음`.

### ③ 네트워크

- [ ] 실습용 Security Group `sg-0acdbff1f820fee1b`의 사용 리소스가 모두 제거된 것을 확인했다.
- [ ] 실습용 Subnet `subnet-0543e9e86dee40c3d`를 삭제했다.
- [ ] VPC에 연결된 Internet Gateway `igw-067455c9fc1f5aee8`을 **Detach**한 뒤 삭제했다.
- [ ] 사용자 생성 Route Table이 있으면 연결 해제/삭제 여부를 확인했다. **현재 사용한 `rtb-0d27123bfa1fd03fe`는 VPC의 메인 Route Table**이므로 VPC 삭제 시 함께 정리되는 항목이며, 메인 상태에서 별도 삭제할 수 없다.
- [ ] 실습용 Security Group을 삭제했다(사용 중이 아닐 때). 기본 Security Group은 VPC와 함께 정리한다.
- [ ] VPC `vpc-0442e2bd8ce7ff488`를 삭제했다.
- [ ] VPC, Subnet, IGW, Security Group과 관련 리소스가 목록에 남아 있지 않은지 확인했다.

**참고:** 콘솔에서 VPC 전체 삭제 기능을 사용하면 일부 하위 리소스를 함께 정리할 수 있다. 어느 방법을 택하든 삭제 결과를 재조회해야 한다. 다른 서비스가 리소스를 사용 중이면 의존성을 먼저 해소해야 한다.

### ④ 정리 후 비용·외부 서비스 점검

- [ ] AWS Billing/Cost Explorer에서 남은 사용량과 예상 비용을 확인했다. 과금 데이터는 지연 반영될 수 있어 즉시 0으로 표시되지 않을 수 있다.
- [ ] EC2 공개 IP로의 접속이 더 이상 서비스되지 않는 것을 확인했다(선택: 종료 증빙).
- [ ] DuckDNS 도메인이 삭제된 EC2의 예전 IP를 가리키지 않도록 레코드를 삭제·수정하거나 운영 종료 처리했다.
- [ ] 필요 없다면 로컬 SSH 개인 키 등 민감한 운영 파일의 보관·삭제 방침을 결정했다. **증빙용 GitHub 저장소에 개인 키를 추가하지 않는다.**
